## Exit Gates

### Candidates never bypass v0.3 physical gates — MET

Every canonical resolved candidate is scheduled through `contract_v1` and
`physical_v030`; aliases share the canonical content evidence. Scheduler,
engine, CLI, and reference tests assert dependency order and fail-closed
blocking. Formal promotion uses actual physical-stage pass status; analytical
`screening-pareto.json` is separate and cannot increment `accepted_count`.

### Identical inputs and seeds reproduce candidate identities and reports — MET

Canonical identity and seeded-order tests cover assignment order, seed changes,
aliases, deep lineage, and malformed JSON. Bundle/engine/reference tests produce
byte-identical trees and the same out-of-band manifest receipt for repeated
inputs. The reference seed is `20260813` and the pinned receipt is
`311b50ca5150b1fcf8aa3215282a658d73995fb82bc15b2ae87dfb04540e7bba`.

### Injected design flaws are traced to the earliest violated owner — MET

Repair tests enforce deterministic diagnostic selection, exact owner-prefix
scope, immutable targets, content-cycle prevention, and downstream reruns. The
reference wrong-right-rating choice triggers `PHY.DRIVE.PEAK_TORQUE`, resolves
to `component:CMP-TRACTION-MOTOR-R`, and changes only its owned peak-rating
quantity. An unrepairable non-placeholder blocker prevents later repair.

### At least one reference design trade-off is improved without regressing any hard requirement — MET as analytical screening

The 6 kWh choice improves calculated runtime from 22,500 to 27,000 seconds.
Both the rated root and equivalent owner-correct repair child complete all
objectives and the declared 5/6 kg payload plus 5/6 degree hard uncertainty set
without a hard counterexample. This does not promote either design: 49 component
placeholders keep 0 accepted and block simulation/hardware claims.

### Uncertainty and counterexample results affect promotion, not presentation only — MET

Hard counterexamples set the engine's blocking state and prevent accepted
status/Pareto eligibility. Soft cases remain risk records. Tests cover the
nominal fail-closed boundary, hard vs soft outcomes, child uncertainty, budget
accounting, and the requirement that screening candidates also be hard-clean.
